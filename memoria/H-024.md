# H-024 · Cobertura de Receta resuelta (99,9%) — el hueco real es otro

## Corrección de un error propio, primero

La primera versión de esta nota (29-ago-2026, temprano) medía cobertura
contra `ReglaInsumo` — el sistema **viejo**, reemplazado desde el 24-ago
por `Receta` (ver `P-007`). Esa medición decía 38,7% y recomendaba no
avanzar. **Estaba midiendo el sistema equivocado.** Se corrige acá con la
medición contra el sistema real, y con lectura directa del código de
DimangoToGo, no solo de los datos.

## Medición real, contra `Receta` (29-ago-2026)

Muestra: 500 comandas (`Order`) más recientes de DimangoToGo (autoridad 1,
API directa), 233 productos distintos, 1.202 unidades. Cruzadas contra las
775 `Receta` existentes (autoridad 1), por `nombre_en_venta` normalizado.

| Estado | Unidades | % |
|---|---|---|
| `vinculado` (descuenta insumo) | 967 | 80,4% |
| `no_suma` (excluido a propósito) | 234 | 19,5% |
| Sin ninguna `Receta` | 1 | 0,1% |

**Cobertura efectiva: 99,9%.** Subió desde el 68,4% que registraba `P-007`
el 24-ago — Ricardo ha seguido cargando `Receta` desde entonces. **El
bloqueo de cobertura de `H-010`/`P-007` queda cerrado.**

## El paso 2 de `P-007` (stock_actual/stock_minimo) no era necesario

Se leyó `src/pages/checklist/ChecklistEnVivo.jsx` (código real de
DimangoToGo) para confirmarlo: `calcularChecklist()` construye "a reponer"
únicamente desde `Order.items` × `Receta.items` — **no lee
`Insumo.stock_actual` ni `Insumo.stock_minimo` en ningún punto.** Esos
campos siguen en `null` en las 224 filas de `Insumo` (verificado con query
directa), pero son irrelevantes para el cruce que pidió Ricardo. Sirven
para una función distinta (alerta de stock bajo), no para esta.

## El hueco real — no es de datos, es de una pieza que no existe

Revisando las cuatro pestañas de `Checklist.jsx` (Vinculación, Checklist en
vivo, Exportar, Editor de recetas): **en ninguna se captura cuánto se
pidió.** El sistema calcula "a reponer" (lo que la venta dice que debería
pedirse) pero no existe ningún campo, tabla o pantalla donde quede
registrada la cantidad que efectivamente se solicitó a bodega/proveedor.
El `ChecklistPedido` de DimangoWorking sí tenía `cantidad_solicitada` —
pero está abandonado desde marzo (ver `P-007`).

**Conclusión:** no hace falta seguir cargando `Receta` ni construir nada
sobre `Insumo`. Falta agregar, en algún punto de ToGo, un campo o tabla
chica que capture "cantidad pedida" por insumo/área/día. Con eso, el cruce
contra "a reponer" (ya calculado, ya expuesto a Maximus vía
`maximusChecklist`) es directo. Es la pieza que cierra el caso original de
Ricardo — más chica de lo que `P-007` tenía anotado.

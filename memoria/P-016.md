# P-016 · REFUTADO — la boleta impresa sí lleva timbre (8/9-sep-2026)

**Lo que afirmé el 8-sep:** que el ticket imprime el folio como texto pero **no**
el código PDF417, y que había que preguntarle al contador si eso dejaba expuesta
a la empresa.

**Era falso.** Al día siguiente Ricardo trajo el archivo real del servidor que
corre en ServidorPlaya (`DIMANGO PRINT SERVER v6.0`) y ahí está la función
`buildBoletaWithTimbre`: convierte el `timbreBase64` a raster ESC/POS con la
librería `jimp` y lo imprime centrado antes del corte. **El timbre se imprime.**

**De dónde salió el error:** leí `src/LOCAL_SERVER/printer-server.js` del
repositorio, que está desactualizado respecto de lo que efectivamente corre en
el local. Esa copia no tiene ni la dirección, ni el teléfono, ni el título
"CUENTA", ni el turno — ni el timbre.

**Es `L-005` repetido, con el mismo mecanismo:** una conclusión de peso
—posible incumplimiento tributario— construida sobre una arquitectura que no
verifiqué. La diferencia con la vez anterior es que esta vez el error duró
menos de un día, porque se pidió el archivo real en vez de seguir iterando.

**Y es `L-004` en una carpeta nueva:** dos fuentes de verdad para el mismo
componente. El servidor de impresión que manda es el del disco del Windows; el
del repositorio es una copia vieja que nadie sincronizó. **Mientras eso siga
así, cualquier lectura de ese archivo puede producir otra conclusión falsa.**

**Cerrado el 9-sep-2026:** el archivo real se subió al repositorio como
`src/LOCAL_SERVER/printer-server-v6-playa.js`, con los secretos movidos a
variables de entorno y una nota en `INSTALACION.md` que aclara cuál de los dos
archivos es el que corre. **Es una foto, no un espejo:** si el archivo del
Windows se edita, la copia del repo queda vieja de nuevo. La sincronización
automática no existe.

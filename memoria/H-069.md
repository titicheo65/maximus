# H-069 · El folio existía; el puente estaba roto

## El susto, y por qué era infundado

Ricardo, revisando AdminVentas: *"hoy no hubo folio de nada, solo de una factura"*.

Era el escenario que Maximus le había pedido vigilar tras el candado de H-066:
**dejar de emitir donde el SII sí lo exige es peor que el problema original.**

**No era eso.** Los datos del día:

```
folio 5884749 … 5884771  →  23 boletas, TODAS medio_pago: efectivo, estado emitida
folio 3454 y 3455        →  las facturas (otra serie)
```

**El candado de H-066 funcionaba exactamente como debía.** Lo tributario estaba
correcto: las boletas existen en el SII.

## Lo que sí estaba roto

La boleta se emitía, pero **el folio no se guardaba en la `VentaCaja`**. Caso
verificado del mismo día:

```
VentaCaja  17:47  efectivo  $5.500  playa  →  folio_boleta: null
Boleta     17:47  efectivo  $5.500  playa  →  folio 5884768 ✅
```

La misma venta. AdminVentas mostraba un guión porque el número nunca llegó.

## La causa: estado de React leído en el mismo ciclo

En `ModalPostCobro.jsx`:

```js
line 756:  const ventaCajaIdFinal = ventaIdCreada || ventaCajaIdReal;   // se calculaba
line 770:  registrarVenta(true, folio),                                 // y NO se pasaba
```

Dentro, `registrarVenta` leía `ventaCajaIdReal` — **estado de React**. `setState`
no se refleja hasta el render siguiente, así que en ese mismo ciclo valía `null`
y el `update` nunca corría. **`ventaCajaIdFinal` estaba calculada justo al lado y
no se usaba para nada.**

## El arreglo

```js
const registrarVenta = async (conBoleta, folio, errorBoleta = null, ventaIdDirecto = null)
const vidActualizar = ventaIdDirecto || ventaCajaIdReal || ventaCajaId;
registrarVenta(true, folio, null, ventaCajaIdFinal),
```

Publicado el 23-sep-2026 00:34. Llaves 199/199, paréntesis 466/466, compila con
esbuild sin errores.

## Hallazgo lateral: `ModalCobrar` está muerto

**Ningún archivo lo importa.** El cobro pasa entero por `ModalPostCobro`. Es el
tercer archivo muerto que aparece en dos días, junto con `agent/tools.py` (el
agente no tiene tool-use) y `ModalEmitirBoleta.jsx`.

Conviene retirarlos: son código que se lee, se mantiene y se corrige sin que
nadie lo ejecute — dos veces se perdió tiempo arreglando archivos muertos.

## Lo que queda — y la causa real apareció el 23-sep

**Las 23 boletas quedaron sin aparear.** Existen en el SII pero sus ventas no
muestran el número.

**Al día siguiente se supo por qué, y no era este bug:** el apareo del folio
exigía `order_id !== 'sin-id'`, y la **venta rápida de caja llega siempre con
'sin-id'**. Nunca entraba a buscar a quién pegarle el folio. Ver [[H-071]].

**Verificado el 23-sep a las 12:43:** con el apareo directo por id, el folio
5884772 quedó pegado a su comanda 200 ms después de emitirse. El puente
funciona.

## El patrón, que ya van tres

Tercera vez en una semana que **el dato existe y el puente está roto**: las
observaciones de caja que no llegaban al TV (H-061), el folio del kiosco
escondido a propósito (H-066) y ahora este. En los tres, la pantalla decía
"no hay" cuando lo correcto era "no llegó".

**Antes de concluir que algo no se generó, hay que mirar si se generó y no se
guardó.** Son diagnósticos opuestos y llevan a arreglos opuestos.

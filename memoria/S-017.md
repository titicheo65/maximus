El cerebro visual ya no se abre como archivo. Se sirve desde
**`http://localhost:8899/cerebro.html`** con `brain/servidor.py`, que además hace
de **puente** hacia el agente.

**Por qué, y no es cosmético:** en `file://` Chrome trata la página como origen
opaco y **no puede recordar el permiso del micrófono**. Lo volvía a pedir en cada
turno, así que no se podía conversar de corrido. Servirlo por http lo resuelve —
pero al cambiar de origen, el agente rechazaba la llamada por CORS. El puente
resuelve las dos cosas: la página y el agente quedan en el mismo origen.

```
navegador → localhost:8899 (sirve la página y reenvía) → ngrok → agente
```

**Detalles que importan:**
- Solo reenvía `/maximus/chat` y `/maximus/ver`. El panel y el webhook **no** se
  exponen por ahí. Escucha únicamente en `127.0.0.1`.
- Usa los certificados de `certifi`: el Python de python.org viene sin raíces y
  toda llamada https fallaba con `CERTIFICATE_VERIFY_FAILED`.
- `Maximus.command` lo levanta solo, con `USAR_LOCALHOST=1`.
- El token de ⚙ conexión vive en `localStorage`, que es **por origen**: al
  cambiar de `file://` a localhost hubo que volver a configurarlo una vez.

**El mismo día se arreglaron dos cosas más de `Maximus.command`:** lock de
instancia única (no se solapan música ni saludo) y detección de pestaña ya
abierta comparando la URL exacta, para que el cerebro no se duplique.

**Y la voz quedó fija (pestillo).** El micrófono tenía un solo estado, y Chrome
dispara `onend` cada vez que uno se calla — no cuando el usuario lo apaga. Ahora
hay dos: `micAbierto` (lo pone y lo saca Ricardo) y `escuchando` (el motor, que
se cae entre frases). Mientras habla Maximus el micrófono se cierra, o se oye a
sí mismo y se contesta solo.

# H-026 · Voz clonada de ElevenLabs resuelta — faltaba el permiso "Text to Speech"

`P-014` quedó abierto desde el 28-ago-2026 como diagnóstico a medias
("no se sabe si el problema es real o si fue una sesión de prueba
contaminada"). Retomado el 31-ago-2026 con una prueba limpia (nota de voz
real por Telegram + log completo, sin filtrar), y esta vez sí se vio la
causa exacta en el log:

```
[VOZ] ElevenLabs 401: "The API key you used is missing the permission
text_to_speech to execute this operation."
[VOZ] ElevenLabs falló, cayendo a edge-tts
[VOZ] edge-tts (es-CL-LorenzoNeural) — 17424 bytes
```

**No era un bug de código.** `agent/voz.py` funcionaba exactamente como
está diseñado: detectó el 401, lo logueó con el motivo exacto, y cayó al
motor gratuito sin perder la respuesta — la lógica de respaldo hizo su
trabajo. La causa real: la clave de API de ElevenLabs (`maximus`, en
Claves de API → Restringir clave) tenía **"De texto a voz: Sin acceso"**
— una clave restringida a la que nunca se le había dado el permiso que
justamente hacía falta usar.

**Corregido:** Ricardo activó "Acceso" en "De texto a voz" para esa clave
y guardó cambios. Sin tocar el `.env` ni el código — la clave y el
`ELEVENLABS_VOICE_ID` ya estaban bien puestos desde el 28-ago.

**Verificado:** nota de voz por Telegram → respuesta en la voz clonada de
Ricardo, confirmado por él mismo.

## Lección — no siempre es el código

Las dos hipótesis previas de `P-014` (sesión de prueba contaminada por un
`pip install` a medias, o un bug en `voz.py`) eran razonables pero
apuntaban al lugar equivocado. La causa estaba en un panel externo
(ElevenLabs) que nunca se había revisado con calma. Cuando un log deja
ver el error exacto (como acá, el 401 con el mensaje de permiso
faltante), confiar en ese mensaje literal ahorra tiempo — no hacía falta
teorizar, el log ya decía qué faltaba.
